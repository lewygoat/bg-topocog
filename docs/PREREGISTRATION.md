## 一、为什么预设判断规则而不是预设数值

用户要求「先对实验结果做预设，然后按预设结果跑」。本方案预设的是**判断规则**，不是**点估计**。

理由：预设点估计再调参至达标，正是评审 R2 与 R8 判定为「研究设计先于结果的原则被倒置」的做法（`defensive_guards.py` 第205–255行的 `verify_preset_targets` 按硬阈值断言、不达标即抛异常）。本方案改为：先写死**什么结果算支持、什么结果算否证**，跑完之后无论数字是多少都不改判据。

## 二、四个待检验假设与判据

### H1 有界门控抑制范数增长（替代原「有界 sigmoid 优于其他」）

**原主张**：`BG-GCN` 的有界 sigmoid 门在 BPR 下优于无界门、向量门、L2 正则、tanh 门。
**问题**：现有数据中 tanh 与 sigmoid 差 0.00028，小于两者标准差，原主张无法成立。

**新假设**：有界化本身（而非具体函数形式）抑制 prior 项的范数增长。

**判据（运行后不得更改）**：
- 主指标：训练结束时 `||φ(g)·W_p·d|| / ||h^(L)||` 的比值
- 支持条件：所有有界变体（sigmoid、tanh、硬截断）的比值均显著低于无界门（配对 t 检验，p < 0.05，n = 5 种子）
- 否证条件：有界与无界的比值差异不显著，或 sigmoid 与 tanh 之间差异显著
- **无论结果如何，论文按实际判据结论书写**

### H2 冷启动上下文的真实增益

**原主张**：`BG-TopoCog` 相对 `Most-Popular` 提升 `HR@10` +99.22%。
**问题**：现有上下文含评测真值，增益主要来自泄漏。

**新假设**：在只使用训练集交互构造的上下文中，`BG-TopoCog` 仍优于最强基线。

**判据**：
- 主指标：`HR@10`，全体冷启动队列 n = 10,748
- 支持条件：`BG-TopoCog` 高于 `Most-Popular` 与 `Skill-Prior + TopoSort` 两者，且配对检验 p < 0.05
- 部分支持：仅高于 `Most-Popular` 但低于 `Skill-Prior + TopoSort`（如实报告为「检索精度占优、覆盖率不占优」）
- 否证条件：不高于 `Most-Popular`，或差异不显著
- **若是否证，摘要与贡献列表的主卖点必须改写，不得保留原数字**

### H3 双约束的独立效应

**原主张**：拓扑约束与认知约束各自贡献。
**问题**：现有数据中两条单约束消融在长视界给出完全相同的覆盖率，无法分解。

**新假设**：在去泄漏与去污染的设定下，两约束存在可分离的效应。

**判据**：
- 设计：2×2 析因（有/无拓扑 × 有/无认知），四视界 M ∈ {5,10,15,20}
- 主指标：`SkillCov`、`Viol_iso`、`Bloom_Smooth` 三项
- 支持条件：交互项在至少两个视界上显著（p < 0.05）
- 否证条件：交互项不显著，此时改为报告主效应并声明两约束可加

### H4 零先修违背是方法性质而非构造结果

**原主张**：`Viol_iso = 0.0000`。
**问题**：解码器读取 `eval_pos_pairs` 做可行性判定，同时用同一集合算指标。

**新假设**：解码器只读 `G_DAG` 时，`Viol_iso` 仍接近零。

**判据**：
- 主指标：解码器仅用 `G_DAG` 生成路径后，对 `E_eval^+` 的实际违背率
- 支持条件：`Viol_iso` ≤ 0.01 且显著低于无约束贪心（p < 0.05）
- 否证条件：`Viol_iso` > 0.01，此时删去「zero violations」表述，改为报告实测值
